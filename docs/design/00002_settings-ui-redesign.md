# 设置页 UI/UX 现代化设计方案

状态:待评审(选定方案后再实施)
关联:`src/views/settings.tsx`(当前实现)、`docs/index.md`

## 现状回顾

- 左侧固定侧栏(w-56):图标 + 文字的导航按钮,激活态为浅灰背景 + 左侧竖条
- 右侧 ScrollArea 单列瀑布:每个设置为独立 Card(rounded border p-4),区块间 space-y-8
- 底部"未保存更改"条仅在 dirty 时出现
- 视觉问题:卡片过多导致碎片化、层级弱(所有设置视觉权重相同)、留白利用率低、
  保存条突兀、与工作区(顶部 tab + 工具栏)的风格语言不统一

以下四套方案均基于现有技术栈(shadcn/ui + Tailwind v4 design tokens + 深色模式),
不引入新依赖。

## 方案 A — "Soft Rows" 分组行式(macOS 系统设置 / Linear 风格)⭐ 推荐

核心思想:**用"组面板 + 行"取代碎片化卡片**。一个区块 = 一个圆角面板,
面板内每行是「左侧标题+描述 / 右侧控件」,行间发丝线分隔。

```
┌────────────────────────────────────────────────────────┐
│ ⚙ Settings                                    [搜索…] │ ← 可选:过滤框
│ ┌──────────┐                                           │
│ │ ◆ OCR    │  OCR SERVICE ──────────────────────────── │
│ │ ⚡ 性能   │  ╭─────────────────────────────────────╮  │
│ │ 📷 截图  │  │ OCR 模式                    [强制本地 ▾]│  │ 行式控件右对齐
│ │ 💾 缓存  │  ├─────────────────────────────────────┤  │
│ │ 📊 Excel │  │ 缓存本地 OCR 引擎             [ ●━○] │  │ 发丝线分隔
│ │          │  │ 常驻模型,省 0.5–2s/次…              │  │
│ │          │  ├─────────────────────────────────────┤  │
│ │          │  │ 并发线程数                     [ 4 ] │  │
│ │          │  ╰─────────────────────────────────────╯  │
│ │          │                                           │
│ │          │  SUPPLIERS ──────────────────────────────  │
│ │          │  ╭─────────────────────────────────────╮  │
│ │          │  │ OpenAI 兼容供应商          [+ 添加] │  │ 折叠面板
│ │          │  ╰─────────────────────────────────────╯  │
│ └──────────┘                                           │
│              ( ( 未保存 · 保存 ) ) ← 居中悬浮胶囊       │
└────────────────────────────────────────────────────────┘
```

**设计要点**
- 侧栏项改为 `rounded-xl`,激活态用主题色 8% 透明度底 + 图标换成主题色 soft square;
  hover 有轻微位移或背景渐显过渡(transition-colors 150ms)
- 面板:`rounded-2xl border bg-card shadow-xs`;行内 padding `px-4 py-3.5`,
  行间 `divide-y divide-border/60`
- 区块标题改为小型大写字距标题(`text-[11px] uppercase tracking-wider text-muted-foreground`)
  + 一句描述,替代现在的图标大标题,信息密度更高
- 供应商列表改为可折叠手风琴(默认折叠已配置项),减少长列表压迫感
- 保存条改为底部居中悬浮胶囊:`backdrop-blur bg-background/80 border shadow-lg rounded-full`,
  出现时 slide-up 动画
- **优点**:改动集中在布局层、最贴近桌面原生感受、双语长度友好
- **缺点**:与现有卡片结构差异较大,需重写各 Panel 的 JSX 结构
- **工作量**:★★☆(约半天)

## 方案 B — "Command Center" 单列居中(Vercel / Stripe 风格)

核心思想:**去掉左侧栏**,单列居中(max-w-2xl)+ 顶部粘性分段锚点条,
靠滚动监听高亮当前小节;增加**设置搜索**。

```
┌────────────────────────────────────────────┐
│        [OCR] [性能] [截图] [缓存] [Excel]   │ ← 粘性分段条(scroll-spy)
│ ╭──────────────────────────────────────╮   │
│ │ 🔍 搜索设置…                          │   │
│ ╰──────────────────────────────────────╯   │
│                                            │
│  OCR 服务                                  │
│  配置识别引擎与触发方式                      │
│  ┌──────────────────────────────────────┐  │
│  │ 行式分组内容(同方案 A 的行语言)     │  │
│  └──────────────────────────────────────┘  │
└────────────────────────────────────────────┘
```

**设计要点**
- 分段条:`sticky top-0 backdrop-blur bg-background/70` 的 pill 组,
  点击平滑滚动;窄窗口自动横向滚动
- 搜索框实时过滤设置项(按 i18n 标题/描述匹配),无结果时显示空态
- 内容最大宽度 ~672px 居中,阅读节奏更好
- **优点**:最现代、实现搜索很自然、移动/窄窗适配最好
- **缺点**:丢失常驻侧栏的方位感;设置项增多后跳转效率略降
- **工作量**:★★★(约一天,含搜索)

## 方案 C — "Glass Drawer" 右侧抽屉(Arc / Raycast 风格)

核心思想:设置不再是独立页面,而是**从右侧滑出的毛玻璃抽屉**叠在工作区上,
随时 Esc 关闭;主工作流不被打断。

```
┌───────────────────────────┬──────────────┐
│                           │ ▓ 设置  [✕] │ ← w-[420px] 毛玻璃
│      主工作区(可见)      │ ▓ OCR 服务  │    bg-background/70
│                           │ ▓ ┌────────┐ │    backdrop-blur-xl
│                           │ ▓ │ …行式… │ │    border-l shadow-2xl
│                           │ ▓ └────────┘ │
└───────────────────────────┴──────────────┘
```

**设计要点**
- 复用现有 Dialog/Radix 或自绘 fixed 容器 + transform 过渡(200ms ease-out)
- 内部沿用方案 A 的行式语言;窄屏自动全宽
- **优点**:现代感最强、上下文保留最好(改完即见效果)、代码量最小
- **缺点**:420px 宽度下供应商表单较挤;与"设置是独立 tab"的心智冲突,
  需要调整 App.tsx 的 tab 结构
- **工作量**:★★★(约一天)

## 方案 D — "Tiles" 双列磁贴(Notion 数据库视图风格)

核心思想:低频开关类设置做成**双列磁贴网格**,每个磁贴自带图标、标题、
一句话描述和控件;复杂表单(供应商)保持全宽。

```
┌───────────────┬───────────────┐
│ ⚡ 缓存引擎   │ 💾 缓存提取   │  ← aspect 自适应磁贴
│ 描述…… [开关] │ 描述…… [开关] │
├───────────────┼───────────────┤
│ 🖥 并发线程   │ ⌨ 快捷键     │
│ [ 4 ]         │ [F8 录制]     │
└───────────────┴───────────────┘
```

**设计要点**:磁贴 `rounded-2xl border p-5 hover:border-primary/40 transition`,
hover 微升(`shadow-md -translate-y-0.5`)
- **优点**:视觉活泼、扫视效率高
- **缺点**:双语描述长短不一易失衡;磁贴隐喻与"精确配置"气质略违和
- **工作量**:★★☆(约半天)

## 共同细节(无论选哪套)

1. **设计 token 统一**:面板 `rounded-2xl`,行分隔 `border/60`,控件高度统一 h-9;
   激活/强调色仅用 `primary`,避免多色混杂
2. **动效克制**:只保留 colors/opacity/transform 三类 150–200ms 过渡
3. **深色模式**:全部走现有 token(bg-card/border/muted),无需额外配色
4. **脏状态增强**:未保存时对应行左侧加 2px primary 竖点标记,保存条显示变更计数
5. **可访问性**:行式布局后 Label 与控件的 htmlFor/aria 关联要补齐

## 建议

优先 **方案 A**(收益/成本比最高,与整体桌面应用气质一致);
若后续想强化"全局命令入口",可在 A 落地后追加 B 的搜索框作为渐进增强。
C/D 作为备选方向保留。

## 2026-10-17 实施修订:分组文字导航 + 一节一卡

状态:已实施(`src/views/settings.tsx`)。本次只重写外壳,`state` / 保存流程 / IPC 一律未动。

方案 A 落地后暴露出几个问题,这次一并处理:

| 问题 | 原实现 | 改法 |
|---|---|---|
| 12 个导航项平级,功能项 / 外观项 / 元信息混排 | `SECTIONS` 单层数组 | `NAV_GROUPS` 分四组:**识别**(模型文件 / OCR 服务 / 截图识别)、**转换**(文本与换行 / 划线表格 / Excel 导出 / 并发与性能)、**外观**、**数据与关于** |
| 一节里堆 5 张独立 `Panel`,碎片化 | 每行一张 `GlassPanel` | `Panel` 退化为"行组"(只有发丝线,无边框/阴影),`<section>` 才是卡片;OCR 服务新增二级小标题(识别引擎 / 版面分析 / 供应商与密钥 / 自定义提示词) |
| 标题弱、不吸顶 | `SectionHeader` 用 uppercase 小灰字 | 卡头 `sticky top-0`:标题 + 一句话说明,实心 `bg-card` + 底部发丝线(见下文为何不用半透明) |
| 保存药丸压住最后一节、且紧贴窗口 ✕ | `absolute bottom-4` 浮层 + 内容仅 `pb-4` | 保存条移到内容**底部独立一行**(`flex-none`,滚动容器之外):左侧「N 项未保存」(悬停列出改动项,计数来自 `dirtyFields` 集合)或「所有更改已保存」,右侧 放弃 / 保存。既压不住内容,也远离右上角的关闭按钮 |
| 滚动同步靠补丁 | 25% 参考线 + `pinnedRef` + 高度为「视口高 − 96」的尾部 spacer | `IntersectionObserver`(`rootMargin: 0 0 -70% 0`)驱动高亮,外加"滚到底"兜底;spacer 与 pinned 全部删除 |
| 控件宽度散乱、无检索 | `w-48` / `w-24` / `w-32` 混用 | 侧栏顶部搜索框(`Ctrl K` 聚焦);`<md` 侧栏隐藏,改用章节下拉 |

**「N 项未保存」怎么来的**:原来整页只有一个 `dirty` 布尔。现在 `markDirty(field)` 把字段 id
记进 `Set<DirtyField>`,`N` 就是集合大小;悬停保存条上的计数会列出具体是哪几项
(`DIRTY_LABELS` 把字段 id 映射到已有的行标题词条,不必新增文案)。字段 id 用
`satisfies Record<string, TranslationKey>` 约束,拼错会在类型检查阶段报错;保存、放弃、
导入配置都会清空集合。代价是 26 处 setter 要带一个字段名,换来的是"改了 3 项"这句话
是真实的,而不是一句笼统的提示。

**页头整块去掉**:内容区顶部的「设置」标题与「改动在点击保存后生效」一句已删除——窗口 tab
条上已经写着"设置",重复一层只白占高度。现在内容列从 md 起没有页头,`ScrollArea` 直接
接在 tab 条下方(内层加 `pt-2` 留一点呼吸);`<md` 时这一行保留,但只放章节下拉。

**导航为什么不用图标**:11 个条目已经足够定位,图标只会多一层需要重新学习的含义
(原先还靠 4 个分组标题补层次,见 2026-10-19 修订——那层已被撤掉)。
窄窗口下没有图标可依托,所以直接隐藏侧栏、改用顶部章节下拉,
而不是退化成一列空图标(原来的 `w-8 md:w-40` 折叠分支在 `minWidth: 800` 下本来也永不触发)。

**滚动容器仍用 Radix `ScrollArea`**:它的内容容器是 `display: table` 的 div,一度担心
`position: sticky` 在这里失效,所以先试过原生 `overflow-y-auto`。实测(在 Chrome 里加载
真实组件,把 `scrollTop` 设到 700 后读卡头相对视口的 `top`)得到 `top = 0`、
`getComputedStyle().position = sticky`,吸顶正常,于是改回 `ScrollArea`,滚动条与其它页面
保持一致。配套改动:卡头背景从 `bg-card/85 + backdrop-blur` 改成**不透明** `bg-card` ——
吸顶条采样下方滚动内容要多一层合成,而窗口本身已经在做玻璃合成,实心卡头也更接近常规
设置页的观感。若将来 Radix 改掉那个 table 包装导致 sticky 失效,再退回原生容器即可
(`scrollViewport()` 是唯一入口,替换成本很低)。

**渲染验证**:除 `tsc` / `vite build` 外,用一次性的 IPC 桩件在 Chrome 里加载真实组件,
确认了窄窗口下拉、吸顶卡头(见上)与导航跟随;桩件与截图均已删除(仓库里不留测试脚手架)。

**遗留**:方案 A 第 4 条"未保存时对应行左侧加竖点标记"仍未做——它需要按字段粒度追踪脏状态,
与当前整页 `dirty` 布尔值不兼容,留到有需要时再单独做。

## 2026-10-19 修订:扁平导航 + 详情级搜索

状态:已实施(`src/views/settings.tsx`)。`state` / 保存流程 / IPC 一律未动。

上一轮的分组(`NAV_GROUPS`:识别 / 转换 / 外观 / 数据与关于)被撤销,侧栏回到
**单层 `SECTIONS` 数组**,顺序与卡片自上而下的渲染顺序一致(点哪一项就落到哪张卡)。
分组标题只是多一层重复信息,而搜索本身已经能定位到行,不需要靠分组来收窄。

搜索从"只匹配 11 个章节标题"升级为**匹配设置项自身的文字**:

| 匹配对象 | 来源 |
|---|---|
| 行标签、行说明 | `SettingRow` / `SubSection` / 提示词块上的 `data-setting-label` / `-desc` |
| 当前选项文案(如选中的 OCR 模式、模型档位) | 行的 `textContent`,即控件里正在显示的那个值 |
| 卡片标题与一句话说明 | 卡头的 `data-setting-head` |

索引在 `useEffect` 里**直接读渲染后的 DOM**(而不是另建一份文案表):所有文案都经过
`t()`,中英文自动覆盖;读到的是**实时值**——下拉框只渲染选中项,所以搜到的是"当前档位"
而非全部选项。搜索时侧栏换成结果列表:`卡片标题 › 缩进的行`,行说明命中时在标题下方
补一行灰字回答"为什么它会出现";点卡片标题跳到卡片顶部,点行则滚动到该行并加
`.doccraft-flash`(1.6s,`index.css`)高亮——行的偏移量按卡头吸顶高度(56px)计算,
否则会被吸顶条盖住。

这版仍然**不复用**方案 A 的"清单式搜索面板",理由同前:11 张卡在桌面上本来就是一列可见内容,
搜索只是把它收窄成"命中行"的路径。

侧栏列表的滚动容器也从原生 `overflow-y-auto` 换成与卡片列同一个 `ScrollArea`(细滚动条观感统一,
`type` 默认 `hover`,鼠标移上去才出现)。代价是 `scrollViewport()` 不能再用"页面里第一个
`data-slot="scroll-area-viewport"`"定位——侧栏的 viewport 在 DOM 里更靠前——改为只在卡片列
(`contentRef`)里查找;跳转/高亮的滚动范围因此仍然只作用于卡片列。
